## 三、各视角关键发现

### 1. 安全（backend/src/productflow_backend）

通过面：11 个 router 全部挂 `require_admin`；下载端点无 IDOR；全项目无 SQL 拼接；SSE 帧经 json.dumps 转义无帧注入；文件名全 uuid/白名单化；SESSION_SECRET 强制、cookie 属性正确；导出脱敏恒定时间比对；`.env` 未被 git 跟踪。

风险 TOP 5：
1. **登录限速退化为全局桶**（`routes/auth.py:25`）：backend 看到的 client.host 恒为 nginx 容器 IP——内网任何人输错 5 次密钥即锁死全员登录。【修 S：解析 X-Forwarded-For】
2. **`/api/settings/unlock` 可无限爆破**（`routes/settings.py:502`）：未复用登录限速器，可暴力猜 SETTINGS_ACCESS_TOKEN。【S】
3. **Prompt injection 链成立**：上传图 vision 打标（`asset_library.py:109`）→ `template_profile_json` 无 schema 白名单 → 直接 f-string 拼进生图 prompt（`tools.py:532`）。共享素材库下可投毒他人出图。【M：字段白名单+长度上限】
4. 门禁关闭态（当前现状）全员裸奔共享 LLM 配额，仅 settings 有二道闸。【有意取舍，公网前必须关门】
5. `/healthz` 公开暴露 provider kind/model/has_key 侦察信息；镜像仅 tag 未锁 digest。【低】

### 2. 后端架构（B+）

亮点：domain/ 零上层依赖；队列幂等（DB authoritative + claim + 1800s 对账）自洽；**技术债密度极低**（TODO/FIXME 全仓 0、type: ignore 仅 5 处）。

债 TOP 5：
1. **loop.py 双路径已漂移出行为 bug**：同步路径的 nudge 在 tool_calls 判定之前（正确），events 路径 nudge 响应的工具调用被静默丢弃（`loop.py:427-440`）→ 流式路径"答应画图却不画"。【S，合并双路径 S-M】
2. `routes/settings.py` 约 400 行应用逻辑在表现层，且是全路由仅有的路由层 commit。【M：下沉 application】
3. `tools.py` 1141 行 12 工具 schema+executor+巨型 if 链同文件。【M：拆注册表】
4. JSON 列（template_profile_json 等）LLM 输出直落无 pydantic 边界。【S-M】
5. 测试盲区：conftest 内联队列使**生产队列路径零覆盖**（Redis 序列化/worker 隔离/pending 部分就绪分支）。【M-L：opt-in broker 套件】

### 3. 前端（web/src，B）

亮点：fetch 全收敛 api.ts、171 处 Query 规范使用、i18n 四语言 856 key 编译期强制齐平、路由全懒加载、manualChunks 已拆、`as unknown as` 仅 5 处全在测试。

债 TOP 5：
1. 巨石页面：SettingsPage 2653 行 / ProductDetailPage 2450 / ImageChatPage 1695 / HelpPage 2853（内嵌文档数据）。【L：按 hook/panel 拆】
2. **WorkbenchPage 中文输入法 Enter 误发**（`WorkbenchPage.tsx:554` 缺 `isComposing` 守卫，image-chat 页已正确处理）——恰是中文主场景。【S】
3. 死契约：前端 `result.report` 后端从不发送 → `CopyReportDetailCard` 是死代码。【S：删或对齐】
4. 动态消息无 aria-live、ConfirmDialog 无焦点圈禁、workbench 三个 query 无错误态 UI。【S】
5. streamAgentMessage 无 AbortController（路由切换后流仍在读）。【S】

### 4. Agent 产品力（B-）

亮点：12 工具三段式 schema 齐、参数 enum 收敛、闭环八环节全覆盖、失败回灌已覆盖生图任务终态。

缺口 TOP 5（按"小白流畅出图"影响排序）：
1. **events 路径 nudge 丢工具调用**（同上架构债 #1）——发生在"首轮只回文字"这一小白最常见路径。【S】
2. **上传→复刻闭环断裂**：前端上传写死 kind=template 且不入对话（`WorkbenchPage.tsx:330`），agent 不知情，用户须口述+agent 检索才能找回刚传的模板。【M】
3. **入队即失败不回灌**（`image_sessions.py:1215`）+ 商品流水线节点失败零回灌——agent 已说"正在生成"而任务已死。【S-M】
4. 20 条历史截断裁掉已确认决策（一轮 2 候选即耗 4-9 条），多轮后小白被迫重述；刷新后工具卡不重放。【M】
5. STAGE_BY_TOOL 仅 6/12 映射，交付/批量后阶段徽章失真；`check_*` 类无"查本会话生成结果"工具。【S-M】
另：工具 schema ≈8-11k token 常驻每轮，成本与延迟偏高。【P2：描述瘦身】

### 5. 运维与文档（C+）

亮点：compose 结构完整（healthy 依赖链、fail-fast、127.0.0.1 绑定）、CI 六道门禁含 tsc、迁移全部实现 downgrade、README 双语且抽查逐字一致、帮助页与代码同步。

债 TOP 5：
1. **三个数据卷零备份零演练**：无 pg_dump/快照外送脚本，误操作 `down -v` 即全损。【L，必须做】
2. **发布不可复现不可回滚**：backend 镜像单阶段+root+pip 现场解依赖（不用 uv.lock），仅 `:local` 覆盖 tag，无 registry/CD。【L，上云前置】
3. 排障盲区：worker 无 healthcheck、healthz 不探测 DB/Redis、无 metrics exporter。【M】
4. 配置漂移：`.env.example` 含死变量（JOB_MAX_ATTEMPTS）、默认值与 compose 相反（gpt-5.4 vs gpt-image-2）、约 15 个 config 字段无 env 文档；`extra="ignore"` 掩盖错配。【S】
5. backend/Dockerfile 层缓存失效（src COPY 在 pip install 之前）+ 版本恒 0.1.0 无 git tag。【M】
