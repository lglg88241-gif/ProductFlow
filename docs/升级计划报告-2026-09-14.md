## 三、升级计划

### P0 对话体验（预计 1-2 天，建议立即做）
1. **SSE 流式对话**——Agent 平均 46s 无任何反馈是当前最大体验痛点；后端已有阶段状态机，补流式管道 + 前端逐字渲染。spec §3 原定 M3 打磨项，正式提上日程。
2. **工具进度实时事件**——生图 26-141s 期间前端只有 spinner；把 durable 任务状态变化（queued→running→progress）推给工作台。
3. **提示词与会话历史瘦身**——system prompt 三层约 1.2K token，历史无裁剪；压缩到近 N 轮 + 摘要，直接降轮次延迟和 token 成本。

### P1 上游稳定性（预计 2-3 天）
4. **生图中转韧性**——URL 下载重试（当前失败即弃）、中转空响应自动重试 1-2 次、单图超时预算与降级提示。
5. **降级链主动健康探测**——启动/定时轻量探测主备，主挂自动预热备用连接；当前是被动切换。
6. **会话上下文管理**——长会话 token 增长控制（截断 + 滚动摘要），避免第 10 轮以后延迟翻倍。

### P2 产品深化（按需排期）
7. **素材库向量检索**——当前词项匹配，升级 embedding 语义检索（中转若支持 embeddings API 即可，零新依赖）。
8. **按模板风格直接生图**——analyze_template 的结构化档案 → 自动转生图 prompt 的模板化链路（识别即可复刻）。
9. **朋友圈多图导出**——九宫格切图/多尺寸批量导出（交付物形态升级）。
10. **商品工作流收编决策**——spec 冻结决议到期复查：agent 稳定后是否收编为"批量流水线"工具。

### P3 工程质量（持续）
11. 覆盖率短板补测：`queue.py`（79%）、`poster/renderer.py`（74%）。
12. 引入 mypy（后端已有完整 type hints 基础）+ 前端 Playwright e2e（复用 demo_flow 剧本）。
13. OpenSpec 引入做 spec 迭代管理（skills 已备）。
14. 观察项：GitHub Actions 首跑状态（badge）；`README` 双语深度校对。

| 风险 | 现状 | 对策 |

## 五、建议执行顺序

**本周**：P0 全部（SSE 流式 + 进度事件 + 瘦身）→ 直接解决"等待焦虑"，这是用户可感知的最大提升。

**之后**：P2 按产品节奏排期，P3 穿插在每次功能迭代中。
