# 升级计划报告（2026-09-15）——稳定性收口 + 对话式设计师功能层

## 背景

在四视角调研（商业竞品 / 开源生态 / Agentic UX / 本地续审）结论上执行两波升级：
第一波为续审核实的稳定性与安全欠账（10 项），第二波为功能层三项（多版本 / 文案报告闭环 / 参数槽重渲）。
执行方式：文件所有权互斥的三组（Wave1）与两组（Wave2）子智能体并行，主控集成回归。

## Wave1：稳定性与安全收口（commit 8aca76d）

| 类别 | 交付 |
|------|------|
| 流式 | nginx `proxy_read_timeout 300s` + `proxy_buffering off`；后端生产者线程 + 15s `: ping` 心跳帧；前端解析跳过注释帧（并修复了一个 boundary 死循环隐患） |
| 对话健壮 | `_build_llm_messages` 构建时跳过"无配对 tool 结果"的孤儿 tool_calls 组——断线不再永久毒化会话 |
| 队列 | worker 常驻对账线程（默认 30 分钟，`RECONCILE_INTERVAL_SECONDS`），运行中滞留任务不再等到重启 |
| 安全 | 新增 `remote_fetch.py`：SSRF 防护（协议白名单、逐跳 DNS 私网校验 IPv4+IPv6、手动重定向复检、30MB 流式上限）；production 下关闭登录门禁直接拒绝启动；登录接口按 IP 失败限速（15 分钟窗口第 6 次起 429）；`/healthz` 不再暴露中转站地址 |
| 超时 | 生图两个 provider 显式 httpx 超时 + 后台轮询整体 deadline（`IMAGE_GENERATION_PROVIDER_TIMEOUT_SECONDS` 默认 300s）；worker failsafe 24h→1h |
| 存储 | 新增 `storage_cleanup.py`（只删无 DB 引用孤儿文件与过期导出，宁漏勿误删，默认 dry-run 语义）+ worker 常驻清理线程（延迟 10 分钟、默认每天一次，`MEDIA_CLEANUP_INTERVAL_SECONDS`） |
| 观测 | LLM usage 落库（AgentMessage 三列 + 迁移 20260914_0033）、`GET /api/metrics/summary` 聚合接口、LLM 调用耗时/模型日志、降级切换 warning（密钥抹除） |
| 部署 | worker 补齐全部 `AGENT_*` 透传；`IMAGE_GENERATE_MODEL` 默认统一 `gpt-image-2`；backend 端口改绑 127.0.0.1 |

## Wave2：功能层（面向"不懂 AI 也能流畅出图"）

1. **多版本 N 选一（A）**：`generate_image` 支持 `count`（1~4，默认 2），tool_result 返回 `candidates`/`primary_url`（队列未就绪时 `pending`+`expected_candidates`）；工作台新增候选对比卡（预览/下载/"用这张继续"）。
2. **文案报告闭环（E）**：`write_copy_report` 剥围栏、兼容 content/sections、落库 `CopyReport`（迁移 20260914_0034）、返回 `download_url`；新路由 `GET /api/agent/copy-reports/{id}/download`（RFC 5987 中文文件名）；工作台报告卡（预览+下载）。
3. **参数槽重渲（B）**：新工具 `rerender_poster_copy`——从商品与最新文案集重建 PosterGenerationInput、局部覆盖文案字段、PIL 本地秒级重渲、落新海报变体；提示词引导"只改文字走它（不耗生图额度），改画面才走 edit/generate（上一轮结果回灌）"。

## 已知边界与后续

- 登录限速为进程内存级（多 worker 不共享）——内部工具够用，公网多实例需换 Redis 计数
- metrics 按日聚合用 UTC 日界；前端用量展示页未做（接口已就绪）
- durable 队列下多候选的 `pending` 形态靠任务状态推断，长会话真实使用需观察
- 向量检索（P2-7）仍 blocked：beeapi 中转无 embeddings 通道
- **暴露到局域网/公网前：必须把 `ADMIN_ACCESS_REQUIRED` 开回 `true`**
