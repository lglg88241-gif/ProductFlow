# ProductFlow 设计师 Agent —— 产品需求与架构设计

- 日期：2026-09-06
- 状态：已批准（用户确认"先按这方案做出来"）
- 路径：brainstorming / Architectural
- 决议来源：grilling 两轮审计 + brainstorming 澄清（Q1=1c，Q2=真需求三项，Q3=3b，Q4=小白可用）

## 1. 产品定义

一个"资深设计师"级的对话式制图 Agent：不懂 AI 的用户以自然对话协作完成制图目标。
系统拥有自己的素材库并能自主整理；能识别用户上传的模板图与文案素材；在引导式对话
（用户不写 prompt、不做调试）后主动给出设计推荐；用户可选用推荐样板或按需求修改；
底层调用主流生图模型。全部能力沉淀为工具集，交互形态类似 Codex——对话即操作。

**成功标准**：一个完全不懂 AI 的人，能流畅地用它产出符合自己要求的图片。

### 真需求清单（用户批改）

- ✅ 参考模板图上传与识别
- ✅ 文/图生图会话
- ✅ 基础设施（供应商/队列/存储/鉴权）
- ⚠️ 商品工作流 DAG：冻结保留（老功能可用，agent 不依赖；稳定后再决定收编为批量工具）
- ⚠️ 海报模板库：内置 3 张作为冷启动样板，归入素材库体系

### 定位约束

- 产品定位：内部工具（不做多租户/SaaS）
- 用户路径：初期由运营者代操作，但 UI 按"老板本人直接对话使用"设计
- 备份：明确不做（已接受风险）

## 2. 架构（方案 A：Agent 编排层 + 现有系统工具化）

```
前端：设计师工作台（对话主界面，图片会话体系演进）
新增：designer_agent 编排层（LLM 工具调用循环 + 引导状态机 + 会话记忆）
工具集：薄封装（生图/改图→provider+队列；素材→素材库；模板识别→视觉模型）
基础设施：Postgres/Redis/Dramatiq/LocalStorage/鉴权（不动）
```

原则：agent 是新增的薄编排层，不是重写。不引入 agent 重框架，自研 tool-calling loop。

## 3. Agent 编排循环

- LLM 调用：OpenAI 兼容 function calling（现有 text provider 层扩展 `tools` 支持）。
- 执行模型：对话轮次在 API 进程内同步执行（LLM 延迟秒级）；生图等长任务走现有
  durable 队列，工具立即返回"已提交 + 任务引用"，前端轮询聚合展示，完成后资产
  出现在会话中，agent 下一轮可引用。
- 引导状态机：`目标澄清 → 方案推荐 → 确认产出 → 交付复盘`；由 system prompt 约束
  每阶段行为；用户随时插话，状态机跟随。
- 数据模型（迁移 0031）：
  - `agent_sessions`：id、title、stage、created/updated
  - `agent_messages`：session_id、role（user/assistant/tool/ system）、content、
    tool_calls_json、tool_call_id、image_session_id（关联产出的图片资产）、created_at
- M1 不做 SSE 流式（响应为完整 JSON，前端 loading 态）；M3 打磨时升级。

## 4. 工具集

| 工具 | M | 行为 |
|---|---|---|
| `generate_image` | 1 | 文/图生图；创建 image session + durable 任务；返回引用 |
| `edit_image` | 1 | 以指定资产为底图改图 |
| `write_copy` | 1 | 结构化文案生成（朋友圈文案/标题/卖点） |
| `save_asset` / `search_assets` | 2 | 素材库写入/语义检索 |
| `analyze_template` | 2 | 视觉模型识别模板图 → 结构化模板档案 |
| `recommend_designs` | 3 | 检索 + 对话上下文 → 推荐卡片（2-3 个方案） |

工具失败（供应商超时/审核拒绝）→ agent 以人话向用户解释并给替代方案；技术细节进日志，
复用现有失败分类。

## 5. 素材库（M2）

- 新表 `asset_library`：类型（模板/参考图/成品/品牌物料）、vision 自动标注（风格/色调/
  主题/场景）、来源（上传/生成）、会话溯源、存储路径（复用 LocalStorage）。
- 自主整理 = 入库时自动打标归类，agent 经 `search_assets` 语义复用。
- 冷启动：内置 3 张 moments 模板。

## 6. 模板识别与推荐（M2/M3）

- 上传模板图 → `analyze_template` → 结构化模板档案（布局/配色/文案位/风格/品类）。
- 推荐 = 检索 + 对话理解 → 推荐卡片；选中后继续对话修改。

## 7. 引导式对话

- System prompt 三层：人设（资深设计师）+ 阶段行为约束 + 工具使用规范。
- 用户零 prompt：agent 负责提问（每轮至多 2 个问题）、猜默认值、给选项。
- 验收：spec 附小白用户剧本（见 §10），作为集成测试脚本与人工验收清单。

## 8. 前端

- 新增"设计师工作台"页（`/workbench`）：对话流主舞台 + 工具/生成进度事件 +
  产出图片内嵌 + 素材库面板（M2）；现有图片会话/商品/画廊页保留。
- 供应商与运行时设置页不动。

## 9. MVP 切分

- **M1 能对话制图**（本 spec 的实现范围）：agent loop + generate_image/edit_image/
  write_copy + 工作台页 + 阶段引导 + 迁移 0031。
- **M2 认得素材**：素材库 + 上传识别 + 检索。
- **M3 像设计师**：推荐卡片 + 自主整理打磨 + 文案报告 + 剧本人工验收。

## 10. 验收剧本（M1 人工验收清单）

> 用户：我要周末做个开业酬宾的海报
> Agent：问 ≤2 个必要问题（行业/店内招牌产品或活动力度），其余用合理默认
> Agent：先给文案 2-3 版供选 → 用户挑一版 → 发起生图 → 告知进度 → 交付成品 +
>       提示可继续修改（换配色/加价格/换尺寸）
> 全程用户未写任何 prompt 式指令。

集成测试以 mock LLM 按剧本回放工具调用序列；人工验收按上表执行。
